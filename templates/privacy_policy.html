{{ _('3. Data Security, Pseudonymization, and Encryption') }}

{{ _('The Platform implements the principles of Privacy by Design and Privacy by Default (Art. 25 GDPR) and, to protect the confidentiality of study participants, enforces strict technical and organizational security measures pursuant to Art. 32 GDPR and in compliance with the Secure Data Handling requirements of the Google Health API Developer and User Data Policy:') }}

  • {{ _('Absence of Identifying Data:') }} {{ _('The application does not collect, transmit, or store names, surnames, tax codes, or any personal information that allows the direct or indirect identification of monitored participants.') }}
  • {{ _('Impersonal Accounts and Data Linkage:') }} {{ _('Wearable device association and synchronization occur exclusively through impersonal project accounts devoid of any personal reference to the user (e.g., wearable_10_ASP_carpi). Integration and linking between different data streams on the Platform (wearable indicators, health assessments, medical device parameters) occur via an internal unique code generated at the database level, completely devoid of meaning or identifying references outside the Platform. This mechanism ensures cross-sectional data pseudonymization and prevents anyone accessing the database from tracing the real identity of the participant.') }}
  • {{ _('Exclusive Decoding:') }} {{ _('The lookup table linking the impersonal account to the real identity of the participant is not available on the Platform; it resides exclusively in restricted internal systems held by the respective competent Autonomous Data Controllers. Technical staff managing the Platform servers have no way of tracing the real identity of the participant.') }}
  • {{ _('Encryption of Data in Transit:') }} {{ _('All data flows between wearables, the Platform, and Google APIs occur exclusively over encrypted and secure protocols (TLS/HTTPS).') }}
  • {{ _('Encryption of Data at Rest:') }} {{ _('Data and access/refresh tokens obtained from Google Health APIs are encrypted at rest in system databases using Fernet encryption (AES-128-CBC with HMAC-SHA256).') }}

{{ _('4. Data Collected and Processing Purposes') }}

{{ _('The Platform processes wellness and vital data exclusively for scientific purposes, lifestyle monitoring, prevention, and promotion of active ageing within the "LivelyAgeing" research study, subject to prior acquisition of Informed Consent from the participant.') }}

{{ _('The processed data consists of two components:') }}

  • {{ _('Data read via Google Health API:') }} {{ _('Subject to explicit user authorization, the application reads and processes exclusively the following types of data required for the study: heart rate, sleep monitoring, steps and physical activity, calories burned, and oxygen saturation (SpO2). Geographic location data (GPS) is neither collected nor processed in any way.') }}
  • {{ _('Additional Project and Integrated Data:') }} {{ _('For cross-sectional integration into the Digital Twin and clinical-functional evaluation, the Platform is designed to receive:') }}
    • {{ _('Wellness and daily routine data: parameters detected by environmental/home automation sensors and lifestyle habits;') }}
    • {{ _('Clinical and cardiac measurement parameters: physiological/electrocardiographic traces and analyses from authorized medical devices;') }}
    • {{ _('Functional and neuropsychological measurement indices: summary outcomes of tests and measurement scales on cognitive performance and general physiological status.') }}
  • {{ _('Purpose:') }} {{ _('Lifestyle monitoring, prevention, and promotion of active ageing within the "LivelyAgeing" research study.') }}

{{ _('5. Data Management and Retention') }}

  • {{ _('Storage Environment and Location:') }} {{ _('All collected and processed data resides at the Data Center of the University IT Systems of UNIMORE, protected by high physical and organizational security standards. These infrastructures include physical access control via restricted badges, 24/7 video surveillance, uninterruptible power supply systems, climate control, and fire protection to ensure continuous integrity and confidentiality.') }}
  • {{ _('Network Security and Access Segregation:') }} {{ _('The application architecture and database reside on segregated virtual machines protected by firewalls. Administrative access to servers and databases is strictly limited to expressly authorized UNIMORE technical platform administrators and occurs exclusively via encrypted and protected communication channels such as SSH and VPN.') }}
  • {{ _('Data Retention Period:') }} {{ _('Pseudonymized data collected from wearables will be retained for the entire duration of the "LivelyAgeing" research project and for the following 2 years, solely to allow scientific validation of the study results. At the end of the retention period, permanent and irreversible anonymization of the dataset stored on UNIMORE servers will be carried out by irreversibly deleting from the database every external linking identifier (including impersonal project accounts), making it impossible to reconnect the dataset to the real identity of the participants.') }}

{{ _('Formal Limited Use Statement:') }} {{ _('The use and transfer to any other app of information received from Google Health APIs by the Lively Ageing Wearable Platform will adhere to the Google Health API Developer and User Data Policy and the Google Health API User Data and Health Research Policy, including the Limited Use requirements.') }}

  • {{ _('Research Requirements:') }} {{ _('Wellness data processing takes place in full compliance with the Google Health API User Data and Health Research Policy for studies approved by an Ethics Committee.') }}
  • {{ _('Limitation of Use:') }} {{ _('Wellness data read via APIs is used exclusively to provide and improve the operational functionalities of the wellness monitoring Platform and for the scientific purposes of the study.') }}
  • {{ _('Prohibition of Sale:') }} {{ _('Collected data will never be sold, transferred to data brokers, or used for advertising, marketing, or commercial profiling purposes.') }}

{{ _('7. Data Subject Rights, Revocation of Google Authorizations, and Data Deletion') }}

{{ _('Pursuant to Articles 15-22 of the GDPR and in compliance with the Google Health API User Data and Health Research Policy, the participant may exercise their rights at any time (access, rectification, integration, erasure, restriction of processing, and withdrawal of consent) without providing any justification and without any consequence on the care services received.') }}

{{ _('Revocation of Google Health API Authorization') }}

{{ _('The participant (or authorized personnel assisting them) may disable data synchronization with the Platform at any time:') }}

  • {{ _('Via Google Account Management:') }} {{ _('By accessing the security section of their Google Account (or the associated project account) under "Third-party apps with account access" and removing authorization for the Lively Ageing Wearable Platform;') }}
  • {{ _('Via Platform / Investigator:') }} {{ _('By requesting the ASP/Municipality contact person or local investigator to disconnect the impersonal project account, which results in the immediate invalidation and deletion of stored OAuth access and refresh tokens.') }}

{{ _('Withdrawal from the Study and Data Deletion') }}

{{ _('In the event of withdrawal from the study:') }}

  • {{ _('Collection and import of new data via Google Health APIs and wearable devices will be immediately and automatically stopped;') }}
  • {{ _('Data already collected associated with the impersonal ID will, upon request of the data subject, be securely deleted from the Platform servers or irreversibly anonymized by destroying the association keys;') }}
  • {{ _('Data already included in scientific publications or research datasets will remain stored in purely aggregated and anonymous form, from which it is technically impossible to trace the identity of the participant.') }}
